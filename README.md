# 🛍️ فروشگاه اینترنتی با Django

این پروژه با هدف **یادگیری عمیق طراحی و پیاده‌سازی یک فروشگاه اینترنتی کامل** با استفاده از **Django** توسعه داده می‌شود. تمرکز اصلی پروژه بر درک مفاهیم معماری، ساختاردهی پروژه، مدیریت وابستگی‌ها، طراحی دیتابیس و پیاده‌سازی قابلیت‌های یک فروشگاه آنلاین در قالب یک **Monolithic Server-Side Rendered (SSR)** است.

هدف این پروژه تنها ساخت یک فروشگاه نیست؛ بلکه مستندسازی مسیر توسعه، تصمیمات معماری و چالش‌های فنی نیز بخش مهمی از آن محسوب می‌شود.

---

# ✨ ویژگی‌های پروژه

- **Framework:** جنگو Django
- **Architecture:** معماری Monolith
- **Database:** دیتابیس PostgreSQL
- **Dependency Manager:** با استفاده ازuv
- **Deployment:** پشتیبانی از اجرای محلی (بدون Docker) و Docker/Docker Compose
- **Documentation:** مستندسازی کامل فرآیند توسعه و تصمیمات معماری

---

# 📂 مستندات پروژه

تمامی مراحل طی شده برای پیاده سازی پروژه در پوشه steps خواهد بود.

| فایل یا پوشه      | توضیحات                                                     |
| ----------------- | ----------------------------------------------------------- |
| `architecture.md` | مستند معماری پروژه، ساختار کلی، تصمیمات فنی و الگوهای طراحی |
| `steps/`          | مستندسازی مرحله‌به‌مرحله فرآیند توسعه پروژه به ترتیب زمانی  |

---

# 📝 مستندات مراحل توسعه (`steps/`)

هر قابلیت یا تغییر مهمی که به پروژه اضافه می‌شود، در قالب یک فایل مستقل داخل پوشه `steps/` ثبت خواهد شد.

نمونه:

<div dir="ltr">

```text
steps/
├── 01-project-setup.md
├── 02-apps-structure.md
├── 03-docker-postgres.md
└── ...
```

</div>

هر فایل باید حداقل شامل بخش‌های زیر باشد:

### 1. چه کاری انجام شد؟

- فایل‌های ایجاد یا ویرایش‌شده
- دستورات اجراشده
- تغییرات اعمال‌شده

### 2. چرا این روش انتخاب شد؟

- دلیل انتخاب راهکار فعلی
- بررسی مزایا و معایب
- مقایسه با گزینه‌های جایگزین (در صورت وجود)

### 3. چه چالش‌هایی وجود داشت؟

- خطاها و مشکلات ایجادشده
- نحوه رفع آن‌ها
- نکات و درس‌های آموخته‌شده

هدف از این مستندات، ایجاد تاریخچه‌ای شفاف از فرآیند توسعه و تصمیمات فنی پروژه است.

---

# 🏗️ نگهداری فایل `architecture.md`

فایل `architecture.md` یک **مستند زنده (Living Document)** است و همواره باید وضعیت فعلی پروژه را منعکس کند.

در صورت ایجاد هرگونه تغییر مهم در پروژه، این فایل نیز باید به‌روزرسانی شود؛ برای مثال:

- تغییر ساختار پوشه‌ها
- اضافه شدن یا حذف یک ماژول
- انتخاب یا جایگزینی یک ابزار
- تغییر در الگوهای طراحی
- تغییرات مهم در مدل داده یا معماری سیستم

به این ترتیب، بدون نیاز به بررسی تاریخچه Commitها، می‌توان تنها با مطالعه این فایل، تصویری دقیق از معماری فعلی پروژه به دست آورد.

این پروژه صرفاً یک فروشگاه اینترنتی نیست؛ بلکه به‌عنوان یک مرجع آموزشی شخصی توسعه داده می‌شود. بنابراین، علاوه بر پیاده‌سازی قابلیت‌ها، تمامی تصمیمات فنی، دلایل انتخاب راهکارها و چالش‌های مسیر توسعه نیز مستند می‌شوند تا روند یادگیری و تکامل پروژه به‌صورت شفاف قابل بررسی مجدد باشد.
